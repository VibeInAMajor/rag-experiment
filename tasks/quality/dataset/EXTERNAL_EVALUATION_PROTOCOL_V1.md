## 1. Validation and evaluator admission

1. Load only [technical manifest](EXTERNAL_TECHNICAL_MANIFEST.md) and [books manifest](EXTERNAL_BOOKS_MANIFEST.md) to enumerate allowed source files. Verify 31 source IDs, each stored SHA-256 and UTF-8 size, no missing or duplicate files, and all local evidence ranges. The corpus is 789,122 bytes; ensure actual parsed chunks <= current 10k and active content <=50 MiB. Never silently bypass parsing, truncate sources or use pre-chunked synthetic records as E2E evidence.
2. Use the existing `scripts/workbench_embedding_evaluate.py` scoring owner and `scripts/workbench_dense_evaluate.py` real HTTP/SQL owner. The Markdown query tables are stable record inputs, not compatible drop-in JSON for the old fixed 52-case fixture. Extend its bounded loader/adapter under DATASET-001 to read each query table and join the matching answer table by Query ID. Extract family/language/intent, candidate answerability, expected answer, source path and #Lstart-Lend anchors, mandatory facet rubric. Validate one-to-one joins, stable IDs, three language variants per family, 261 candidate answerable and 45 candidate no-answer rows. Escape Markdown table separators and code tokens correctly. Do not introduce another evaluator or scorer. Reviewers must turn textual facet rubrics into explicit source-span/alternative mappings and grade labels before admission. Existing scorer's chunk-ID labels and 100-query cap require reviewed bounded extension, not silent truncation.
3. For each original evidence line range, map exact UTF-8 source bytes and text offsets through the real parser/chunker to actual persisted source/version/chunk identities. Preserve original source and normalized representation lineage; duplicate translations or repeated facts can be reviewed as alternative primary evidence. Never treat all unjudged chunks as grade 0. For unsupported markup/math/table rendering, record NOT_EVALUABLE or qualify a deterministic derived representation with versioned mapping.
4. Agent source verification: validate source authority and each expected fact, exact formula, number/unit, historical attribution, fiction context and alternative/supporting/hard-negative evidence. Review all candidate no-answer queries against the entire eligible corpus (including near-topic passages). This visible 306-case set is diagnostic/regression data, not a local held-out split. Group EN/RU/UK translations, source families, duplicated facts and same-book excerpts; never split translations into independent train/test sets. Retain a separate local holdout for QUALITY-002, with source and query-family leakage checks. No special custody, reviewer accounts or human approval required.

## 2. Actual end-to-end run

- Start a new owned disposable PostgreSQL test DB with existing explicit migrations and restricted application role; use the actual supported Markdown upload/parse/chunk/publication path for 31 original corpus files, authorized development workspace, safe idempotency keys and source hashes. Do not modify main corpus. Verify the actual generation and eligible counts.
- Backfill through current durable embedding worker and attested local Qwen3-Embedding-4B / 2560-dimension TEI profile with fresh expiring shared capacity configuration; no per-evaluator independent TPM budget. Require complete matching embedding coverage and version fences. Verify FTS and exact Dense Live readiness, never Preview.
- Run all admitted question IDs through actual API. Compare FTS, exact Dense, RRF and optional BM25/reranker variants only when their tasks qualify. Use identical corpus/source scope and final token budget, preserve raw candidate ranks and selected context separately. Independently verify exact SQL identities/distance for exact path. Separate actual inference/SQL/HTTP wall latency; do not fabricate GPU kernel time or ranking results.
- Run evidence-selection and answerability when available, and later grounded generation for each admitted case. Compare generated answer claims, exact identifiers, numeric/formula values, source evidence and citation support against localized expected answers; compare semantics, not exact string equality. Use a second agent source-checking pass for interpretation/claims and disclose uncertainty. No-answer false acceptance and false abstention require a real decision, not a forced nearest-neighbor list.

## 3. Required metrics and gates

For both repository and external tracks publish separate run manifests, counts, cohort/domain/language outcomes and per-case failures. Compute source/evidence Primary Hit@1/5/10, relevant evidence recall, primary MRR, graded nDCG and All Required Facets at fixed context budget; for math check exact numeric/formula and units; for code exact identifiers and behavior; for art/literature attribution and original narrative claims. Source/page/line correctness, authorized current version, profile and generation are mandatory. For 87 families report macro over families and language results; 261 translated answerable cases are correlated. Compute family-clustered confidence intervals, not independent binomial bounds over all translations. No-answer cases have null retrieval recall, explicit false-acceptance/false-abstention denominators and service-error counts. Compare external domain weaknesses instead of averaging them away.

Targets follow QUALITY-001/002: primary@1 >=95%, primary@5 >=98%, relevant recall@5 >=95%, nDCG@5 >=95%, all-required-facets >=95%, critical cohort primary@5 >=95%, no observed unauthorized/stale/wrong-profile/citation integrity errors; answerability false acceptance/abstention <=5% after implementation. These are proposed target estimates, not measurements. This open dataset can diagnose and gate regressions but cannot replace a fresh local held-out split or establish statistically adequate per-domain production confidence. Report failure, BLOCKED, NOT_EVALUABLE, or NOT_TESTED explicitly. Run real model/SQL/API and affected regression commands using repository Hatch conventions and record exact artifacts under tasks/evidence/. No runtime tests or human review are implied by the static collection.

## 4. Anti-leakage and regression rules

Index ONLY corpus files. Questions, reference answers, notices, evaluation reports, source manifests, task specifications and fixture labels must remain evaluator-only. Do not give gold facts, language variants or holdout queries to the runtime model/ranker. Questions are intentionally visible for open diagnostics; a later local held-out split must be separate. If one source or label changes, increment the dataset revision; preserve previous results. Use the same reviewed label version for paired baselines. Never use external web lookups to answer during testing; information must originate from the frozen corpus. Never label a technical error as no-answer.
